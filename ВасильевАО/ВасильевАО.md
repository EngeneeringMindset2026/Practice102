# Лабораторная работа № 2. Тестирование open-source проекта

## 1. Цель работы
Получение практических навыков тестирования open-source проектов, анализа покрытия кода, написания модульных тестов (unit-тестов) и внесения изменений в открытый проект через GitHub Pull Request.

## 2. Выбранный проект
**Название:** humanize
**Репозиторий:** https://github.com/python-humanize/humanize
**Язык программирования:** Python
**Описание:**
Humanize — библиотека Python, предназначенная для преобразования чисел, размеров файлов, дат и временных интервалов в удобный для восприятия человеком формат.
Для выполнения лабораторной работы был создан Fork репозитория и настроено локальное окружение для запуска тестов.

## 4. Анализ исходного покрытия
Для запуска тестов и измерения покрытия использовалась команда:
```powershell
.\.venv\Scripts\python.exe -m pytest --cov=humanize --cov-report=term-missing
```
До внесения изменений общее покрытие составляло **98,75% (554 из 561 операторов)**.
В файле `src/humanize/number.py` были обнаружены непокрытые участки кода, связанные с обработкой некорректных аргументов и локализованным форматированием чисел.

## 5. Написанные unit-тесты
Новые тесты были добавлены в файл `tests/test_number.py`.

### 5.1. Проверка обработки некорректного формата
**Тест:** `test_clamp_invalid_format`
Проверяется, что функция `clamp()` вызывает исключение `ValueError`, если передать недопустимый тип аргумента `format`.
Для проверки исключения используется `pytest.raises`.

### 5.2. Проверка локализованного форматирования чисел
**Тест:** `test_intcomma_localized_separators`
С помощью `pytest.mark.parametrize` добавлены два сценария:
- Форматирование числа `1234567.89` в строку `1.234.567,89`.
- Форматирование числа `1234567.89` в строку `1 234 567,89`.
Для подмены разделителей тысяч и дробной части используется `monkeypatch`.
Все три добавленных тестовых сценария успешно прошли проверку.
